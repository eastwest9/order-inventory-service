# Order Inventory Service - Phase 1

## 1. 프로젝트 목표

대량 동시 주문 환경에서 재고 초과 판매와 데이터 불일치를 방지하고,
동시성 제어 전략별 정확성과 성능을 비교하는 주문·재고 서비스를 구현한다.

Phase 1에서는 쇼핑몰 전체 기능을 구현하는 것이 아니라,
상품·재고·주문의 핵심 업무 흐름과 재고 정합성 문제에 집중한다.

---

## 2. Phase 1 핵심 도메인

- 상품(Product)
- 상품 판매 단위 / SKU(Product Variant)
- 재고(Inventory)
- 재고 이력(Inventory History)
- 주문(Order)
- 주문 상품(Order Item)
- 최소 회원(Member)

회원은 Phase 1에서 실제 인증 기능을 구현하지 않고,
주문의 소유자를 표현하기 위한 최소 데이터만 사용한다.

---

## 3. 주요 기능

### 3.1 상품

- 상품 등록
- 상품 목록 조회
- 상품 상세 조회
- 상품 판매 상태 변경
- SKU 등록 및 조회

### 3.2 재고

- 초기 재고 생성
- 재고 입고
- 현재 재고 조회
- 주문에 따른 재고 차감
- 주문 취소에 따른 재고 복구
- 관리자 재고 조정
- 재고 변경 이력 조회

### 3.3 주문

- 주문 생성
- 주문 목록 조회
- 주문 상세 조회
- 주문 취소
- 재고 부족 주문 실패 처리
- 중복 주문 취소 방지

---

## 5. 동시성 검증 목표

대표 테스트 조건은 다음과 같다.

- 초기 재고: 100개
- 총 주문 요청: 1,000건
- 요청당 주문 수량: 1개
- 동일 SKU에 요청 집중

### 기대 결과

- 성공 주문: 100건
- 실패 주문: 900건
- 최종 재고: 0개
- 재고 음수 없음
- 초과 판매 없음

다음 값은 반드시 일치해야 한다.

성공 주문 수량 합계
= 초기 재고 - 최종 재고
= 재고 차감 이력 수량 합계

---

## 6. 비교할 동시성 전략

다음 전략을 동일한 테스트 조건에서 비교한다.

1. 동시성 제어 없음
2. synchronized
3. Optimistic Lock
4. Pessimistic Lock
5. Conditional Atomic Update

최종 전략은 사전에 결정하지 않고
정확성 및 성능 테스트 결과를 기준으로 선택한다.
